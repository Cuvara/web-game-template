# CrazyGames requirements

Every requirement the official documentation states for an HTML5 game, what in this
repository answers it, and how that answer is checked. Read from
<https://docs.crazygames.com/> on **2026-09-23**. CrazyGames does not version its docs, so
the date is the version; re-read the linked page before relying on a row.

The official documentation is the source of truth. Where this page and the docs disagree,
the docs win and this page is wrong.

## Basic Launch and Full Launch are different states

CrazyGames launches in two steps
([requirements intro](https://docs.crazygames.com/requirements/intro/),
[FAQ](https://docs.crazygames.com/faq/)):

|          | `BASIC_LAUNCH`                                    | `FULL_LAUNCH`                                                                                        |
| -------- | ------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Entry    | Passes initial QA                                 | Selected on Basic Launch KPIs, then QA'd again                                                       |
| SDK      | Optional; if present, `gameplayStart` is required | Required: gameplay start/stop, Data/User where applicable                                            |
| Ads      | Disabled; SDK answers `adsDisabledBasicLaunch`    | Only through the SDK, per the ad requirements                                                        |
| Gameplay | Basic visual QA, PEGI 12                          | Full visual QA, **land directly in gameplay** (max 1 click)                                          |
| Accounts | No external logins                                | Progress linked to the CrazyGames account, username/avatar, auto-login — where the game has accounts |

A build that meets Basic does not meet Full, and nothing in this repository reports one as
the other. The adapter implements the **Full Launch** SDK integration (a superset of Basic).
At runtime it can only _observe_ the stage: `CrazyGamesPlatform.observedLaunchStage` is
`basic` after an `adsDisabledBasicLaunch` answer, `full` after an ad actually starts on a
CrazyGames domain, and `unknown` otherwise. Which stage a game is in is decided by
CrazyGames, not by the build.

## Architecture

```
Game (examples/crazygames-compliance-demo/src/main.ts — or a title's src/)
 ↓   Platform contract only: initialize, gameplayStart/Stop, showInterstitial/showRewarded,
 ↓   adAvailability, storage, settings, environment, events
Platform interface   packages/platform-sdk/src/types.ts
 ↓
CrazyGames adapter   packages/platform-sdk/src/adapters/crazygames/platform.ts
 ↓   the only code that touches window.CrazyGames
CrazyGames SDK v3    https://sdk.crazygames.com/crazygames-sdk-v3.js (observed 3.8.0)
```

## Status vocabulary

| Status                   | Meaning                                                                      |
| ------------------------ | ---------------------------------------------------------------------------- |
| `AUTOMATED`              | Implemented, and a test or the audit fails if it regresses                   |
| `APPROXIMATION`          | Measured here, but the portal measures it itself; our figure is not theirs   |
| `MANUAL_REVIEW_REQUIRED` | Cannot be decided by code — a person, or the CrazyGames QA tool, has to look |
| `GAME`                   | The template gives the mechanism; each title must do it for itself           |
| `NOT_APPLICABLE`         | Does not apply to the demo (and says why)                                    |
