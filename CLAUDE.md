# CLAUDE.md

Instructions for Claude Code (and any coding agent) working in a game repository created from
**web-game-template** (Web Game Factory, template contract 2). The full Factory ↔ template API
is [docs/factory-contract.md](docs/factory-contract.md); this page is the part you act on.

## What this repository is

One web game for HTML5 portals (Poki, CrazyGames, Yandex, GameDistribution, GameMonetize, Y8,
GameVui, self-hosted). The template supplies the loop, renderer, platform adapters, boot
sequence, build, tests and release tooling. You write the game.

- Engine: `engine.type` in `game.config.yaml` (`pixijs` or `threejs`). Use only that one.
- Platforms: `platforms[]` in `game.config.yaml`. One build per platform; you never pick one
  in code.
- If `docs/development/brief.md` exists, it is your assignment. Report back in
  `docs/development/report.json` in the shape the brief gives.

## The one entry point

```ts
// src/game/index.ts
export async function createGame(context: GameContext): Promise<GameHandle>;
```

`src/main.ts` boots the platform, strings and renderer, then calls `createGame` with
everything wired (`src/game/context.ts`), then signals ready and starts the loop. Inside
`createGame`: build scenes (`context.game.changeScene(...)`), UI in `context.ui`, input,
audio; report loading with `context.reportLoadingProgress(0..1)`; return
`{ audio?: { mute(), unmute() }, dispose?() }`. Replace `BootScene` (`src/game/boot-scene.ts`)
with the game's own scenes.

## Working with Claude Code here

- Use the Bash tool for the `pnpm` commands below; run long browser suites in the background
  and read their output rather than re-running them.
- Plan edits against the lists below before touching a file; a protected-path edit is
  rejected by the Factory however good it is.
- The same instructions are in `AGENTS.md` for other agents; keep the two in step.

## Where you may write

- `src/game/**` except `context.ts` and `integration.ts`
- `src/ui/`, `src/audio/`, `src/input/`, `src/assets/`, `src/analytics/`
- `src/rendering/pixijs/` or `src/rendering/threejs/` — the only place `pixi.js` / `three`

the template.

- `src/main.ts`, `src/core/`

## Rules

- Never import or reference a portal SDK (`YaGames`, `PokiSDK`, `window.CrazyGames`,
  `gdsdk`, `sdk.showBanner`, `y8`, …) or call a `Platform` method from game code. Never call
  `createPlatform`.
- Advance game state only in fixed-step `update()`; never with `requestAnimationFrame` or
  `setTimeout`.
- Do not write `#hud[data-ready|data-scene|data-steps|data-engine|data-platform]`; `main.ts`
  owns them. Scene ids reach `data-scene` automatically via `Game.changeScene`.
- Do not weaken, skip or delete a test to get green.
- Do not add another engine; the tech plan chose one.

## Ads, analytics, saves

Call the seam, nothing else:

- `context.integration` (`GameIntegration`): `gameplayStart()`, `gameplayStop()`,
  `canOfferRewarded(id)`, `rewarded(id) → Promise<boolean>`, `interstitial(id)`,
  `track(event, props?)`, `load(key)`, `save(key, value)`.
- or `context.gameplay` (`PlatformGameplay`) at moment level: `runStarted()`, `gameOver()`,
  `levelComplete()`, `pause()`, `resume()`, `continueFrom(moment)`,
  `canOfferReward(moment)`, `offerReward(moment)`, `naturalBreak(moment)`, `save`, `load`.

Placement ids are the game-design's placement ids, verbatim. Hide a rewarded offer when
`canOfferRewarded` is false; grant the reward only when `rewarded()` resolves `true`.
`interstitial()` always resolves; continue either way. The plan that maps ids to moments
(`src/platform/integration-plan.ts`) is generated by the Factory — do not edit it; with the
template default (no placements) offers are hidden and breaks are no-ops, which is correct.
Silence audio through the `GameHandle.audio` you return and respect `context.audio.muted`.

## Browser tests

- `pnpm test:e2e` builds nothing: run `pnpm build` first. It serves `dist/` with
  `pnpm preview` (port 4173) and runs Playwright projects `desktop` and `mobile` over
  `tests/e2e/`. First time on a machine: `pnpm exec playwright install chromium`.
- Add a spec as `tests/e2e/<name>.spec.ts` with `@aspect` tags in the test title, e.g.
  `test("restarts after game over @game-over @restart", …)`. Tags: `@boot` `@loading`
  `@start` `@input` `@core-loop` `@progression` `@game-over` `@restart` `@pause-resume`
  `@responsive`. The Factory maps tests to aspects by these tags; the inherited specs cover
  `@boot @loading @core-loop @pause-resume @responsive`, so a game adds `@start`, `@input`
  (controls), `@progression` (a progression loop) and `@game-over @restart` (an end condition).
- Wait for `#hud[data-ready="true"]`, then drive the game with real input
  (`page.keyboard`, `page.mouse`, `page.touchscreen`) and assert through the probe
  `window.__wgf__`: `scene()`, `steps()`, `paused()`, `framesRendered()`, `moments()`
  (gameplay moments recorded: `{ name, moment, placement, atMs }`), `engine`, `target`.
  Expose game state with your own `data-*` attributes on `#hud` or `#ui` when needed.

## Before you finish — run all, in order, all must pass

```bash
pnpm install --frozen-lockfile   # after dependency edits: pnpm install, then commit the lockfile
pnpm format:write
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm sdk:check
pnpm test:e2e
```

## Verify and release (run by CI and the Factory; know what they check)

- `pnpm build:platforms` builds every platform into `build/platforms/<id>/dist/`. A missing
  portal id (y8 `app_id`, gamemonetize/gamedistribution `game_id`) fails the build.
- `pnpm test:verify` boots each artifact with portal SDKs blocked and measures runtime facts:
  loading API called, no insecure requests, mobile support, time to interactive, throttled FPS.
- `pnpm facts --platform <id>` adds static facts: bundle size, shipped locales, which portal
  SDK the bundle contains (must be exactly its own), declared ad kinds. Requesting an ad kind
  not in `monetization.ad_kinds` fails.
- `pnpm assert --platform <id>` judges facts against the pinned profile; a blocking breach
  fails.
- `pnpm release:package` refuses a build that is missing, stale against `HEAD`, built with
  `WGF_ALLOW_UNCONFIGURED_PORTAL=1`, modified after build, over the profile's size cap, or
  lacking `index.html` at its root.

## Working on the template itself

When this checkout is `web-game-template` (`game.id: example-game`), the rules above invert:

- `packages/`, `src/main.ts`, `src/core/`, `src/platform/`, `scripts/` and the test configs
  are yours to change; game code (`src/game/boot-scene.ts`) stays a minimal scaffold.
- Any change to what [docs/factory-contract.md](docs/factory-contract.md) states is a
  contract change: update that page, `CHANGELOG.md`, and bump `wgf.template.contract` in
  `package.json` if it breaks games.
- Keep both engines working: the untouched template's suites build pixijs and threejs.
- Also run `pnpm test:sdk:browser`, `pnpm build:platforms`, `pnpm test:verify` and, when
  `examples/` changed or the game API moved, `pnpm golden:check`.
- Style: TypeScript strict, ESM, Prettier (printWidth 100, double quotes, trailing commas);
  comments say why and cite portal docs.
